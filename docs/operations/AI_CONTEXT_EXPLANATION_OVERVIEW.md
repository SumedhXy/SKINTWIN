# Milestone 6.9: AI Context & Explanation Layer

## Objective
The AI Context & Explanation Layer converts structured computer-vision metrics (OpenCV alignment, MedSAM segmentation, observable measurement changes) into user-friendly, structured JSON reports. It serves as an interpretative layer to help users understand what the ML pipeline measured, without inventing clinical conclusions.

## Architecture

1. **Input Contract**: The backend processes two images, aligns them, segments the Region of Interest (ROI), and extracts changes in area, color, shape, boundary, and position. It computes a reliability score and identifies any uncertainties. This structured output is passed to the AI layer via the `ComparisonExplanationInput` Pydantic model.
2. **AI Provider Abstraction**:
   - `BaseAIProvider`: Interface for generating explanations.
   - `DeterministicAIProvider`: The default provider. Zero external dependencies. Uses rule-based templates to translate changes into human-readable text. Guarantees safe, accurate reflections of ML measurements.
   - `LLMProvider`: An optional integration (e.g. Gemini) that generates rich contextual explanations. It enforces a strict structured JSON schema generation constraint and falls back to deterministic on errors/timeouts.
3. **Validation & Medical Safety Rules**: 
   - Never diagnose, predict disease, or claim clinical accuracy.
   - Never assume missing values mean "no change".
   - Numerical values generated by the ML pipeline are strictly preserved.
   - Standard, immutable medical disclaimers are forcibly injected into the output schema.
4. **Persistence**: The generated AI explanation is cached in the PostgreSQL database under the `Comparison` table in the `ai_explanation` text column.

## API Endpoints

- **`GET /api/v1/comparisons/{comparison_id}/explanation`**: Retrieves the cached AI explanation, or generates one on-the-fly using the active AI provider if none exists.
- **`POST /api/v1/comparisons/{comparison_id}/explanation`**: Forces regeneration of the AI explanation and overwrites the DB cache.

*Authentication (JWT) and SkinTwin ownership checks are strictly enforced.*

## Provider Configuration
To use an external LLM (like Gemini):
```env
AI_PROVIDER=gemini
GEMINI_API_KEY="your-api-key"
```

If these are not set, or the API call fails, the system seamlessly uses the `DeterministicAIProvider`.
