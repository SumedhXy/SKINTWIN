# SkinTwin Privacy Requirements

**Version:** 1.0 (Milestone 7.5)
**Last updated:** 2026-09-18
**Status:** Development — not formally assessed for regulatory compliance

This document describes what personal data SkinTwin collects, why it is collected,
and how it is handled. It is based on the actual implementation, not aspirational claims.

---

## 1. Data Collected

### 1.1 Account Data

| Field | Purpose | Required |
|---|---|---|
| Email address | Account identification and login | Yes |
| Password (bcrypt hash only) | Authentication | Yes |
| Display name | UI personalization | No |
| Account status | Session management | Yes |
| Created-at timestamp | Account lifecycle | Yes |
| Last-login timestamp | Session tracking | Yes |

**What is NOT stored:** Plaintext passwords. Passwords are hashed using bcrypt before
storage. The plaintext password is never persisted.

### 1.2 SkinTwin Metadata

| Field | Purpose |
|---|---|
| Name, body location, body side, description | User-defined skin finding record |
| Status (active/archived/needs_review) | Monitoring workflow |
| Capture count | UI summary |
| Timestamps | Timeline ordering |

### 1.3 Capture Data

| Field | Purpose |
|---|---|
| Image file (JPEG/PNG/WebP) | Visual record of the skin finding |
| SHA-256 hash of image | Duplicate detection |
| Image quality metadata | Determine comparison eligibility |
| Notes | User annotations |
| Device metadata | Capture context (optional) |
| Timestamps | Timeline ordering |

**Image storage:** Images are stored as files in the server's local filesystem under `uploads/`.
They are not stored on the user's device. They are served only to the authenticated owner via
the `/captures/{id}/image` endpoint.

### 1.4 Comparison Data

| Field | Purpose |
|---|---|
| Reference to two captures | Comparison input |
| MedSAM/OpenCV measurement results | Observable image-level measurements |
| Reliability and uncertainty metrics | Technical reliability indicators |
| AI explanation text | Contextual summary |
| Processing status | Workflow state |

**AI processing:** AI explanations are generated by the OpenAI API via the backend.
The backend sends structured measurement results (not raw images) to the OpenAI API
to generate the explanation. See Known Limitations for more detail.

### 1.5 Find Care Data

Find Care provider discovery uses mock fixtures labeled `[TEST DATA]`.
No SkinTwin data, images, AI explanations, or personal health information is sent
to provider records or third-party APIs during provider discovery.

Location data (when used) is processed in the Flutter app to query the backend.
Coordinates are not stored server-side.

---

## 2. Data NOT Collected

- Biometric data (biometric lock is not implemented)
- Continuous GPS tracking (location is used only on explicit user action)
- Precise persistent location records
- Third-party analytics or telemetry
- Health diagnoses or medical conclusions
- Social or behavioral profiles

---

## 3. Authentication Data Handling

- Passwords are hashed with bcrypt before storage. The plaintext is not logged or retained.
- JWT access tokens are stateless. No token blacklist or refresh token system is implemented.
- Token expiry: 30 minutes.
- On logout, the client deletes the token locally. Server-side token invalidation is not possible
  with the current architecture.

---

## 4. Location Data

- Location is not required to use SkinTwin.
- Location is requested only when the user taps "Use My Location" in Find Care.
- Location is processed on-device for the geocoding reverse lookup (city name).
- Coordinates are not stored on the backend server.
- Permission is requested at the time of action, not at app startup.

---

## 5. AI Provider Data

- AI explanations are generated via the OpenAI API.
- The backend sends structured JSON (measurement deltas, reliability metrics) — not raw images.
- The backend's OpenAI API calls are subject to OpenAI's data handling policies.
- Users should not include personally identifying information in SkinTwin names or notes,
  as those fields may appear in the AI prompt context.

---

## 6. Image Privacy

- Images are private by default. No public image URLs are generated.
- Images are served only via `GET /captures/{id}/image` with a valid JWT for the owner.
- Find Care requests do not include or reference SkinTwin images.
- Sharing permissions exist in the data model but sharing features are not implemented in the UI.

---

## 7. Data Retention

- Data is retained until the user deletes a SkinTwin, a capture, or their account.
- No automatic expiry policy is currently implemented.
- Server backups (if any) are outside the application's control and may retain data
  beyond what the application-level deletion achieves.

---

## 8. User Deletion Rights

Users can:
- Delete individual captures via `DELETE /captures/{id}`
- Delete a SkinTwin (and all its captures) via `DELETE /skintwins/{id}`
- Delete their account (and all data) via `DELETE /users/me`

Account deletion requires password re-authentication and removes:
- User record
- All SkinTwins and captures (database)
- All image files (storage) — if file deletion fails, the failure is logged

**Known limitation:** If the backend server has external backups, those are not
controlled by the application. The system does not guarantee data is unrecoverable
from all possible storage systems.

---

## 9. Data Export

Users can request a JSON export via `GET /users/me/export`.

The export includes:
- Profile metadata
- SkinTwin metadata
- Capture metadata (not raw image files)
- Export notes explaining scope

The export does NOT include:
- Password hashes
- JWT tokens or secrets
- Raw image files
- Other users' data
- Internal system metadata

---

## 10. Sharing

SkinTwin data is not shared automatically with any external party.
A `SharingPermission` model exists in the database, but sharing UI features
are not implemented. No sharing will occur without explicit user action.

---

## 11. Known Limitations

1. **JWT logout:** Tokens remain valid on the server for up to 30 minutes after logout.
2. **Server backups:** Application-level deletion does not guarantee removal from server backups.
3. **OpenAI API:** Structured comparison data is sent to OpenAI. Raw images are not.
4. **File orphans:** If image file deletion fails during account deletion, a file may be orphaned.
5. **No formal audit:** This system has not undergone a formal third-party privacy or security audit.
6. **No regulatory compliance claim:** This document does not assert GDPR, HIPAA, or similar compliance.

---

## 12. Contact

This is a development application. There is no formal data controller or privacy contact
at this stage.
